当模型大到单张 GPU 放不下，或者单卡吞吐无法满足服务需求时，通常需要把计算或数据分布到多张 GPU 上。最常见的三种方式是：数据并行（DP）、张量并行（TP）和流水线并行（PP）。它们解决的是不同问题，不能简单地说哪一种“最好”。

## 一张表先看懂

| 方式 | 切分对象 | GPU 之间主要通信什么 | 更适合 |
| --- | --- | --- | --- |
| DP | 输入 batch | 梯度或参数 | 模型能放进单卡的训练、服务扩容 |
| TP | 层内矩阵和计算 | 激活、部分结果 | 单层或模型放不进单卡，节点内高速互联 |
| PP | 模型层 | 中间激活 | 超大模型训练，跨节点扩展 |

## 数据并行：复制模型，切分数据

数据并行在每张 GPU 上放一份完整模型，每张卡处理不同的 mini-batch。训练完成后，需要同步各卡的梯度，使模型参数保持一致。常见的同步操作是 All-Reduce，它可以分解为 Reduce-Scatter 和 All-Gather 两个阶段。

数据并行的优点是实现简单、扩展性好，缺点是每张卡都需要保存完整模型。对大模型来说，梯度、优化器状态和参数同步都会产生很大的通信量。推理场景中，数据并行通常表现为多个完整副本加负载均衡，适合用来提高并发，而不能解决“模型放不下一张卡”的问题。

## 张量并行：切分一个矩阵乘法

以 `Y = XW` 为例，可以沿着 `W` 的列切分，让不同 GPU 计算不同的输出列；也可以沿着行切分，让每张 GPU 计算部分乘积，最后通过 All-Reduce 合并结果。

张量并行让多张 GPU 同时参与同一层计算，通常能获得较好的单请求性能，但代价是层与层之间需要频繁通信。因此 TP 更依赖 NVLink 等高速互联，跨节点使用时则会受到网络带宽和延迟的明显影响。

## 流水线并行：切分模型层

流水线并行把连续的模型层放到不同 GPU 上。输入先经过第一段，再依次传递给后面的阶段。它能把非常大的模型分散到很多张卡上，但如果只有一个请求，很多 GPU 会在等待，形成流水线气泡。

训练时通常将一个 batch 切成多个 micro-batch，让不同阶段同时处理不同 micro-batch，以减少气泡。micro-batch 越多，设备利用率通常越高，但调度和激活保存的复杂度也会增加。

## 实际组合

大型训练往往采用 DP + TP + PP 的三维并行：TP 负责单层切分，PP 负责层间切分，DP 负责复制整个并行组并处理更多数据。推理服务则常见 TP 加数据并行副本；如果模型过大，还会结合 PP 或专家并行。

选择并行策略时，先回答三个问题：模型是否能放进单卡、GPU 之间的互联带宽是多少、目标是降低单请求延迟还是提高总吞吐。并行度越高不一定越快，通信成本必须和计算收益一起测量。
