# 介绍
增强检索生成（RAG）由Retriever和Reader组成，一般用于问题回答、事实验证等任务。以问题回答为例，Retriever会根据问题从一系列文档中选择出一部分能够帮助Reader回答问题的文档，Reader阅读完选取的文档后再回答问题。这样就可以让Reader获得Retriever的辅助，起到如虎添翼的效果。

一般来说，Reader都是大模型，Retriever检索得到的文档内容会被直接插入到提示词中输入给大模型。大模型就可以根据文档给出经得起检验、支持考据的回答了。
# 经典流程
1. 收集文档，将文档拆分为若干个可搜索的**块（chunks）**，组成知识库；
2. 根据查询（query）的内容，在知识库中查询，将最有可能帮助完成任务的一组块返回；
3. 返回的块被插入到提示词中，大语言模型根据提示词给出回答。
# 优缺点
1. 优点：
	1. 可以通过更新知识库，轻易做到与时俱进（重新训练大模型成本很高）；
	2. 大模型回答的内容有根据，可以进行考据；
	3. 可以很好应对专业任务。
2. 缺点：
	1. 难以应对知识密集型任务（搜索不全）；
	2. 检索的内容中的噪声很影响大模型发挥；
	3. 块被看作独立单位，无法考虑信息之间的逻辑联系。
# 改良
1. 提示词重写
2. 多段检索+重排序
3. 把块组织起来，提高检索完整性，如 IIER
