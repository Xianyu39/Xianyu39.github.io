混合专家（Mixture of Experts，MoE）把一个大的稠密 FFN 拆成多个专家，并让每个 token 只激活其中一部分。它的目标不是让同等总参数量的模型天然更强，而是在保持较大参数容量的同时，减少每个 token 的实际计算量。

## FFN 为什么适合拆成专家

一个 FFN 可以写成：

$$\operatorname{FFN}(x)=f(xW_a)W_b$$

如果把矩阵按专家切分，就可以把结果理解为多个子网络输出的组合。MoE 再增加一个 router，根据 token 的表示给专家打分，只选择 top-k 个专家：

$$y=\sum_{i\in\operatorname{TopK}(r(x))}g_i(x)E_i(x)$$

这样，模型的总参数量可以很大，但单个 token 的激活参数量相对较小。

## 路由与负载均衡

最直接的路由策略容易让大量 token 集中到少数专家，造成部分专家超载、其他专家空闲。为此，训练时通常会加入负载均衡损失，鼓励 token 分布和路由概率分布更加均匀；工程上还会设置 capacity limit，超出容量的 token 需要丢弃、溢出到其他专家或采用共享专家。

均衡不是越强越好。过度约束会削弱路由器学习到的专业分工，因此实际需要在专家利用率、模型质量和通信成本之间调参。

## 分布式 MoE 的通信

如果专家分布在不同 GPU 上，一个 token 可能需要先通过 All-to-All 发送到目标专家，再把结果发回原设备。此时瓶颈不只在计算，也在网络通信和 token 重排。专家并行的部署需要同时关注互联拓扑、batch 形状、容量因子和尾延迟。

MoE 的收益可以概括为：用稀疏激活换取更大的参数容量。但它并没有消除显存、通信、路由不稳定等问题，只有在端到端测量中吞吐和质量都满足目标时，才算真正获得收益。
